01. Overview & Architecture

Turing Service is a multi-tenant voice calling orchestration platform built with FastAPI. It acts as a management and analytics layer on top of the Bolna voice engine, providing:

  • Multi-tenant isolation — each client (tenant) gets their own API keys, agent configurations, phone number assignments, and call data
  • Batch call management — upload CSV or JSON recipient lists, schedule calls, monitor execution
  • Real-time analytics — call volume, duration, cost, and outcome breakdowns with time-series support
  • LLM-powered call analysis — automatic classification of call outcomes (booking, escalation, follow-up, etc.)
  • Admin console — full lifecycle management of clients, agents, phone numbers, and drift detection
  • SQL Builder Agent — natural-language-to-SQL query interface for analytics

Technology Stack

02. Quick Start

Get from zero to your first API call in three steps.

Step 1 — Register

curl -X POST https://your-domain:8005/v1/register \
  -H "Content-Type: application/json" \
  -d '{"name": "Acme Health", "contact_email": "dev@acme.com"}'

Step 2 — Get Your API Key

After an admin approves your registration, you'll receive an API key via the claim link (or directly from the admin). The key looks like tsk_abc123....

Step 3 — Make Your First Call

curl https://your-domain:8005/v1/calls \
  -H "X-API-Key: tsk_your_api_key_here" \
  -H "Content-Type: application/json"

# Response: list of your calls (empty initially)

Step 4 — Create a Batch

curl -X POST https://your-domain:8005/v1/batches \
  -H "X-API-Key: tsk_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "agent_id": "your-agent-id",
    "recipients": [
      {"recipient_phone_number": "+919876543210", "user_data": {"name": "John"}}
    ]
  }'

03. Authentication

Tenant API Key (X-API-Key)

All tenant-scoped endpoints require the X-API-Key header. Keys are issued per-client and can have multiple active keys with optional labels.

GET /v1/calls HTTP/1.1
Host: your-domain:8005
X-API-Key: tsk_abc123def456...
Key Caching: API keys are cached for API_KEY_CACHE_TTL_SECONDS (default 60s) after first lookup. Key revocation takes effect after cache expiry.

Admin Key (X-Admin-Key)

All /v1/admin/* endpoints require the X-Admin-Key header. This is a single shared secret set via the ADMIN_API_KEY environment variable.

GET /v1/admin/clients HTTP/1.1
Host: your-domain:8005
X-Admin-Key: your-admin-secret

Webhook IP Allowlist

The /webhooks/voice endpoint restricts access by source IP. Configure allowed IPs via VOICE_WEBHOOK_ALLOWED_IPS (comma-separated). An empty value allows all IPs.

Error Responses

StatusCondition
401 UnauthorizedMissing or invalid API key
403 ForbiddenClient is suspended or inactive

05. Rate Limiting

Rate limiting is enforced at the service layer using Redis (with an in-memory fallback when Redis is unavailable).

EndpointLimitWindow
POST /v1/registerREGISTER_RATE_LIMIT_PER_HOUR (default: 10)1 hour, per IP

When a limit is exceeded, the API returns 429 Too Many Requests. Implement exponential backoff in your client.

08. Portal & Claim Links

The portal enables clients to look up their account, and claim links provide a one-time secure mechanism for distributing API keys.

MethodPathAuthDescription
POST /v1/portal/lookup Open Look up client by name or email
GET /v1/claim/{token} Open Preview claim link (non-destructive)
POST /v1/claim/{token} Open Burn claim link and receive API key

Claim Flow

  1. Admin approves a client → system generates a one-time claim URL
  2. Client visits GET /v1/claim/{token} to preview (see org name, expiry)
  3. Client calls POST /v1/claim/{token} to consume the token and receive their API key
One-time use: Claim tokens expire after CLAIM_LINK_TTL_HOURS (default 24h) and are destroyed on first successful consumption. Store the returned API key securely.

Response — POST /v1/claim/{token}

{
  "client_name": "Acme Health",
  "api_key": "tsk_live_a1b2c3d4e5f6..."
}

16. SQL Builder Agent

Status: Disabled — Not Currently Available. The SQL Builder Agent is paused and its endpoint is not mounted in the running application. The feature requires a dedicated read-only PostgreSQL connection (KALAAM_READONLY_DATABASE_URL) and LLM API keys that are not configured in the current deployment. The router is gracefully skipped at startup when dependencies are unavailable. This section is retained for future reference.

Natural language to SQL query interface. Ask questions about your call data in plain English. Requires X-API-Key and a configured Kalaam read-only database connection.

MethodPathStatusDescription
POST/v1/sql-agent/queryDisabledSubmit a natural language query

Prerequisites (when re-enabled)

The SQL Builder Agent requires the following environment variables to be configured before it can be activated:

Example (for future reference)

# This endpoint is currently disabled. When re-enabled:
curl -X POST https://your-domain:8005/v1/sql-agent/query \
  -H "X-API-Key: tsk_your_key" \
  -H "Content-Type: application/json" \
  -d '{"question": "How many calls were completed last week with a booking outcome?"}'
Safety (when enabled): The SQL agent connects via a PostgreSQL role with default_transaction_read_only=on and a configurable statement_timeout. All generated queries are validated with EXPLAIN before execution and scoped to the tenant's data.

17. Webhooks

Inbound — Voice Engine Callback

MethodPathAuthDescription
POST /webhooks/voice IP Allowlist Receives call status updates from the voice engine

This endpoint is called by the Bolna voice engine to report call status changes, transcripts, and extracted data. Configure TURING_PUBLIC_URL so the voice engine knows where to send callbacks.

Outbound — Call Outcome Notifications

When a client configures a webhook_url in their client config, Turing sends a POST request for each completed call with outcome data.

Webhook Payload

POST https://your-webhook-endpoint.com/callback
Content-Type: application/json
X-Turing-Signature: sha256=abc123...

{
  "call_id": "exec_abc123",
  "agent_id": "agent-001",
  "voice_batch_id": "vb_xyz789",
  "contact_number": "+919876543210",
  "status": "completed",
  "duration": 45.2,
  "outcome": "booking",
  "summary": "Patient confirmed appointment"
}

Signature Verification

If webhook_secret is set, Turing signs the request body with HMAC-SHA256. Verify using:

import hmac, hashlib

def verify_signature(body: bytes, secret: str, signature: str) -> bool:
    expected = "sha256=" + hmac.new(
        secret.encode(), body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, signature)
